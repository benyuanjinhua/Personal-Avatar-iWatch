# ESS-53 Watch 交互体验重构：竞品研究、交互方案与状态机映射

> 状态：MVP 实现随本文档同 PR 交付；真机用户测试（≥3 人）与产品验收（白梦林）待后续轮次。
> 约束：与 ESS-52（P0 真机稳定性）隔离——本次不改动 WatchVoiceTransport / VoiceTurnJournal /
> WatchSettingsStore / VoiceRelay* / iOS PhoneConnectivity 等传输与状态入账层，只改表现层。

## 1. 目标回顾

小屏 + 单手 + 抬腕几秒的使用窗口下，用户要一眼知道五件事：

1. **何时说** —— 就绪态有清晰的"按住说话"承接。
2. **是否收到** —— 松手即有触觉 + 视觉确认，录音没白说。
3. **处理到哪** —— 已到手机 / 已到 Mac / 思考中，可分辨、可离开。
4. **何时有结果** —— 结果到达主动响铃 + 触觉 + 自动播放，不需要盯屏幕。
5. **如何重试** —— 每种失败都有明确的下一步，不出现死胡同。

## 2. 竞品观察与取舍

### 2.1 Siri（watchOS 内置）

| 观察 | 采用？ | 理由 |
| --- | --- | --- |
| 抬腕即说 / 长按数码表冠触发，零导航成本 | ⭕ 部分 | 我们保留"打开 App 首屏即语音球"，一步到位；抬腕唤醒依赖系统私有能力，第三方拿不到 |
| 聆听时全屏波形 + 收音结束立即转"思考"动效 | ✅ | 语音球已有波形/脉冲双态，本次补齐触觉（开始 .start / 结束 .stop） |
| 结果以卡片呈现，可滚动回看 | ✅ | 结果卡片 + 全文字幕视图已具备，本次补播放控制 |
| 无明确"已送达服务器"中间态 | ❌ 不学 | Siri 链路短所以能藏；我们是 Watch→iPhone→Mac 三跳，中间态必须显式，否则失败无法归因 |

### 2.2 ChatGPT（iOS/watchOS 语音模式）

| 观察 | 采用？ | 理由 |
| --- | --- | --- |
| 超大单按钮，全屏状态色区分听/想/说 | ⭕ 部分 | 语音球即"单按钮"，状态色已按模式区分；不做全屏纯色（表盘小，保留状态文案信息量更高） |
| 思考中有持续动效，用户可打断 | ✅ | 处理中球体脉冲；"取消本次请求"保留且始终可达 |
| 回答边生成边播（全双工流式） | ❌ 不学 | 非目标：MVP 明确不做持续全双工音频流；watchOS 后台流式电量代价大，且 WC 链路不保序 |
| 文字与语音同屏、逐句跟随 | ✅ | ESS-48 字幕式播放已实现，本次补暂停/继续/重播 |

### 2.3 Just Press Record

| 观察 | 采用？ | 理由 |
| --- | --- | --- |
| 打开即一键开录，零配置 | ✅ | 首屏即语音球；欢迎语文案直接教"按住说话"，30 秒内可完成首问 |
| 录音时大号计时 + 波形，安全感强 | ⭕ 部分 | 波形已有；录音上限 60s 在副标题提示（"松开发送（最长 60 秒）"），不加大号计时（表盘空间给状态文案） |
| 点按开始/点按结束（toggle 模式） | ❌ 暂缓 | 按住说话（walkie-talkie 模式）误触率更低、心智更简单；toggle 作为后续可选设置再评估（见 §9） |
| 后台继续录、录完自动同步 | ✅ 已有 | ESS-45 ExtendedRuntimeSession + outbox 队列已覆盖 |

### 2.4 微信（watchOS 按住说话）

| 观察 | 采用？ | 理由 |
| --- | --- | --- |
| 按住说话、松开即发、上滑取消 | ⭕ 部分 | 按住/松开已有；"滑动取消"在 40mm 表盘上与滚动手势冲突，改为录音后仍可点"取消本次请求" |
| 发送后消息列表可见排队状态 | ✅ | 状态时间线保留每回合完整轨迹 |

### 2.5 总结：交互原则

1. **单手三动作走完主链路**：按住 → 松开 → 听结果；其余全部自动。
2. **触觉是第一反馈通道**：抬腕窗口短，视觉可能错过；每个关键节点都有触觉（见 §4 反馈矩阵），结果到达另有响铃 + 自动播放兜底。
3. **状态可分辨、可离开**：三跳链路的每一跳用户可读（已到手机 / 等待 Mac / 思考中），且明确告知"可以先离开，任务在后台继续"。
4. **失败必须给下一步**：每种失败给出差异化的恢复动作（自动重发 / 立即重试 / 重说），不出现只有红叉没有出路的界面。
5. **调试信息离开主链路**：request_id、Relay 原始状态、收件箱等移入诊断页，普通用户主屏零噪音。

## 4. 状态机 → 用户投影 → 反馈矩阵

内部状态机（`Shared/VoiceTurnState.swift`，§6 协议，本次不改流转逻辑）：

```
recorded → waiting_for_phone → waiting_for_mac → accepted → realtime_processing
→ background_accepted → background_processing ⇄ permission_required
→ completed / failed / cancelled
```

用户投影（`VoiceTurnPhase`）与全通道反馈：

| 内部状态 | 用户投影 | 视觉（球色/图标） | 触觉 | 音频 |
| --- | --- | --- | --- | --- |
| （按下） | 我在听 | 紫球 + 实时波形 | `.start` | — |
| （松开） | 正在送出 | 青球 + 时钟脉冲 | `.stop` | — |
| recorded / waiting_for_phone | 等待手机连接 | 青球脉冲 + "已排队，手机连上后自动送出" | — | — |
| waiting_for_mac | 已到手机，等待 Mac | 青球脉冲 | `.click`（送达确认） | — |
| accepted | 已送达 | 蓝球脉冲 | —（避免连环震动） | — |
| realtime/background_processing | 处理中 / 后台处理中 | 蓝球脉冲 + "可以先离开" | — | — |
| permission_required | 需要确认 | 橙球 + 感叹号 | `.notification` | — |
| completed | 已完成 | 绿球 + 对勾 | `.success` | 结果语音自动播放（ESS-41 B3） |
| failed | 失败（分环节，见 §5） | 红球 + 叉 | `.failure` | — |
| cancelled | 已取消 | 灰球 | — | — |

实现要点（`Shared/TurnFeedbackPolicy.swift` + `Watch/WatchHaptics.swift`）：

- 触觉由**状态机变迁**驱动而非 UI 挂载：策略层对 journal 快照做 diff，同一回合同一状态只触发一次，乱序/重复事件天然去重（复用状态机的单调前进约束）。
- **冷启动静默 seed**：重开 App 恢复历史回合时不补发触觉，只对"本次观察到的变迁"反馈，避免开屏震动风暴。
- 触觉总开关沿用 iPhone 伴侣 App 已有"触感反馈"配置（`AgentConfiguration.hapticsEnabled`），经 ApplicationContext 同步到手表。

## 5. 失败分型与恢复文案

技术错误 → 人话 + 差异化恢复动作（`VoiceFailureStage.recoveryHint`，新增）：

| 场景 | 标题 | 恢复提示 | 动作 |
| --- | --- | --- | --- |
| 手机不可达（发送前/中） | 失败：手机未连接 | 靠近 iPhone 后会自动重发 | 失败卡提供「立即重试」（触发 outbox 重提交，request_id 不变、接收端幂等） |
| Mac 未响应 | 失败：Mac 未响应 | 语音已在手机上，Mac 恢复后继续；也可重说一次 | 按住重说 |
| 执行失败/超时 | 执行失败 | 按住语音球，再说一次 | 按住重说 |
| 没听清（空录音） | 没有录到语音 | 请再试一次，说话时保持抬腕 | 按住重说 |
| 麦克风无权限 | 没有麦克风权限 | 到手表"设置 > 隐私"允许腕语使用麦克风 | 引导设置 |
| 录音器启动失败 | 无法开始录音 | 请稍后重试 | 按住重说 |

等待类（非失败，不打断）：无网络/等待手机 → "已排队，手机连上后自动送出"；等待 Mac →"任务在后台继续，可以先离开"。两者与失败态严格区分：等待态青/蓝球 + 无触觉，失败态红球 + `.failure`。

## 6. 播放控制：播放 / 暂停 / 重播

现状问题：结果语音只有"播放"，播放中按钮禁用；播完即从加密仓删除（交付后删除策略），无法重播。

方案（不动删除策略与 ACK 语义——那是交付协议，属 ESS-45/46/47/52 的地盘）：

- `SpeechPlayer` 增加 `pause()` / `resume()`（`isPaused` 状态），字幕视图与结果卡片同步显示 暂停/继续。
- **内存重播缓存**：`PushToTalkController` 在播放前把解密后的音频保留在内存（仅最近一条），播完后加密仓照删、ACK 照发，但本次会话内可"重播"。退出 App 缓存即失（可接受：重播是"刚才没听清"场景，跨会话回看走文字全文）。
- 权衡说明：把音频持久保留会改变"交付后删除"的隐私承诺与重投判定，收益（跨会话重听）小于风险，舍弃。

## 7. 锁屏 / 后台 / 恢复

均为已有能力，本次只在文案上显式承接：

- 录音→等待→播放全程 ExtendedRuntimeSession 保活（ESS-45），降腕不断播。
- 退出 App 后任务继续（outbox + WC 托管队列），重进从 VoiceTurnJournal 恢复最近回合与结果。
- 结果语音后到时按 request_id 定向自动播放（ESS-41 B3），不依赖 UI 挂载。

## 8. 30 秒首用路径

冷启动 → 欢迎语（音频 + 横幅"按住语音球开始对话"）→ 按住（.start 触觉 + 波形）→ 说话 → 松开（.stop 触觉 +"正在送出"）→ 状态逐跳推进（送达 .click）→ 结果响铃 + 自动播放 + 字幕逐句高亮。全程零菜单、零配置、单手指。
